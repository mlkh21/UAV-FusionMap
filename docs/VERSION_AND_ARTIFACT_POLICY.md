## 1. 工程文件与版本边界

本仓库维护系统规范、工程接口、适配源码、配置和小型验证记录。研究仓库独立维护，
不复制研究数据、权重、环境或结果到主仓。第三方飞控/仿真源码仅作为固定版本的
运行依赖保存在.runtime，不成为主仓业务源码。

继续使用feature/engineering-initialization；尚无首次提交，未跟踪文件不能据此视为
可由Git恢复。首次提交须核对实际文件清单后另按授权执行，不使用git add .。
首次候选清单为根AGENTS/README/PROJECT_STATUS/.gitignore、各模块AGENTS和现有目录
占位、docs工程文档、algorithms来源登记及experiments内的小型Markdown验证记录。
SIM-00A新增的环境配置、命令环境入口与构建说明亦纳入逐文件候选审查；
`.runtime/CATKIN_IGNORE`是唯一允许进入候选清单的.runtime文件。
具体清单以提交时逐文件审核为准，不把整个目录的未来新增文件自动纳入授权。

main仅承载验收基线，develop承载已检查的集成，feature/*承载任务。尚无提交时不创建
虚假的main/develop历史；首个经授权的提交建立后再按基线状态创建或流转分支。
文档版本、候选依赖和已经验证的运行版本分别标注，禁止仅因写下版本号就宣布稳定。

## 2. 忽略与catkin隔离

[根.gitignore](../.gitignore)仅排除明确的本机目录：.runtime中的生成资产、原有.codex
会话配置，以及ros_ws常见构建输出。不使用*.json、*.yaml、data或models等宽泛规则
隐藏后续接口配置或模型描述。`.runtime/CATKIN_IGNORE`保留为可提交的边界标记。

catkin隔离标记先于依赖源码填充建立，防止外层catkin_ws扫描嵌套第三方包。
忽略规则不删除文件，也不保护已经被Git跟踪的文件；每次提交仍需检查索引。
运行依赖位置是本机配置，不得写死到系统公共接口或复制到研究仓库。

## 3. 目录、记录和保存责任

| 相对本仓库根的位置 | 内容 | 保存要求 |
| --- | --- | --- |
| .runtime/downloads/ | 实际取得的deb、数据包、版本元数据与来源清单 | 保留原始资产以支持复现，不能只保留下载URL |
| .runtime/src/ | 固定提交的独立第三方源码及子模块 | 登记完整提交、子模块、Git状态和本地调整；不修改原始外部仓库 |
| .runtime/deps/ | 项目专用的依赖前缀、工具环境和geoid数据 | 登记构建/解包方式、搜索路径及实际版本，不污染研究Conda |
| .runtime/build/、.runtime/ros/ | 可重新构建的输出与日志 | 对应源码、环境、实际命令明确后才称可复现 |
| .runtime/logs/sim00a/ | 本次构建命令、失败/成功输出、版本和检查记录 | 与下载包和源码共同保存；/tmp不作为持久证据目录 |
| .runtime/runs/<run_id>/ | 单次启动rootfs、bag、标准输出、参数、计数和退出状态 | 每次新目录；不覆盖旧run或无关进程输出 |
| experiments/ | 本轮目的、修改清单、验证结果及产物索引 | 小型记录纳入候选提交，失败和未执行项保留 |

每次构建/运行保存manifest，至少包含日期、责任角色、任务、源版本、实际环境、命令、
输入/输出位置、退出码及验证边界。单次run另记录时钟域、run_id、坐标、场景和参数。
不为目录存在或记录身份增加无意义的哈希；下载资产校验如有需要，应使用发布方或
软件包索引提供的完整性元数据，不把自生成标识冒充发布方验证。

初期所有产物保持原位，不自动清理失败构建、旧bag、数据或日志。运行前记录磁盘
可用空间，大型产物或清理另明确范围；禁止把清理系统或研究目录作为恢复步骤。
