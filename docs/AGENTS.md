# docs 模块规范

基线：v0.1；日期：2026-09-11；责任角色：system_architect / project_manager。
先读[根规范](../AGENTS.md)、[项目状态](../PROJECT_STATUS.md)和[系统架构](SYSTEM_ARCHITECTURE.md)。

## 1. 模块职责

维护系统设计依据、数据契约、坐标规范、开发计划和决策、实验索引。

## 2. 输入输出定义

输入为用户需求、当前实现、已批准决策及验证记录；输出为可追踪的中文工程文档。
字段语义归DATA_FORMAT，坐标归COORDINATE_SYSTEM，连接行为归SENSOR_INTERFACE。

## 3. 允许修改范围

在已确认范围内维护本目录Markdown及必要的文档图示；同时修正受影响的文档引用。
每份规范标明版本、状态、责任角色和日期。

## 4. 禁止修改范围

不得为文档任务修改业务代码、移动外部算法或覆盖实验产物；不得把草案、占位、离线
回放或语法通过写成运行能力。不得删去失败记录或未经评审改变架构和验收门槛。

## 5. 与其他模块接口关系

根AGENTS规定流程，SYSTEM_ARCHITECTURE规定分层。模块文档引用共同契约，不各自
重定义同名字段。docs/EXPERIMENT_LOG索引experiments内的详细记录。

## 6. 测试要求

核对文件覆盖、相对链接、代码证据位置、字段/单位/坐标一致性和状态用词。
设计检查、静态代码检查、实际运行和场景验收分别记录；不要求为纯文档新增业务测试。

## 7. 文档要求

决策记录状态和依据；待决项必须有责任角色、目标日期和阻塞范围。新结论引用当前
证据；旧决策被替代时保留记录。完成后同步PROJECT_STATUS和相关索引。
