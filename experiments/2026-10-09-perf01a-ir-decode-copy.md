# EXP-20261009-001：匹配入口 IR 临时复制候选

- 日期：2026-10-09；主责任：integration_engineer；状态：已完成对照，候选未达采纳门槛。
- 问题：匹配器在 ROS IR 回调中先将整幅 `float32[]` 转成新的 Python 列表，
  随后有界匹配缓存又复制该列表以取得独立所有权；640×512 图像多一次容器复制。
- 唯一候选：为异步匹配器增加默认关闭的诊断开关，仅在回调内部借用
  已反序列化消息的像素列表，交给匹配器同步复制并持有；通用解码接口默认行为、
  ROS 消息、像素值、缓存所有权及在线输出不变。保留关闭开关以直接回退。
- 不改变：5 ms 同步门限、40 ms 匹配截止、10 ms 位姿年龄、严格拒绝理由、
  20 ms P99 目标、时钟归属或在线 LiDAR 边界。

先用单元测试验证默认解码副本、候选借用关系以及匹配器接收后独立持有列表；
再对零噪声 `normal`、70 m/s、`exact`、640×512、每次 2 s 的真实 ROS
短测按 A-B-B-A 串行运行（A：开关关闭；B：开关开启，端口依次
12152/12153/12154/12155），每次追加独立 `.runtime/runs/` 目录，
不覆盖旧产物；对照不额外增加 match/wire 插桩，仅保持现有分段及端点探针。
每 run 必须通过原有严格 oracle：40 Radar/100 IR 收据、20 采用/20
`radar_ir_timeout`、20 个 Bundle/占据/地图身份闭合、唯一 clock、清理通过。
对照记录同一 Radar 回调到占据 P99 及 IR 回调 `decode_ns` 分布；
按两组 P99 的中位数比较，B 相对 A 至少降低 10% 且四 run 均过 oracle
才考虑作为候选默认实现，结果有明显波动或失败则保留默认关闭。
这只有 2+2 条短测，不能作为正式性能统计、设备时间戳或功耗证据；
即使达到相对门槛但仍高于 20 ms，也不得宣称 PERF-01 完成。
