# tests 模块规范

基线：v0.1；日期：2026-09-16；责任角色：tester / reviewer。
先读[根规范](../AGENTS.md)、[项目状态](../PROJECT_STATUS.md)和[系统架构](../docs/SYSTEM_ARCHITECTURE.md)。

## 1. 模块职责

负责跨模块接口、集成与系统验收；模块内部单元测试随各模块维护。
Phase 0只建立验证要求，不为文档初始化编写算法测试代码；后续随实现任务建立必要测试。

## 2. 输入输出定义

输入：需求编号、公开契约、实现、已知场景和验收阈值。
输出：可复现的检查结果、失败证据和覆盖范围；未执行或被阻塞必须单独列出。

## 3. 允许修改范围

经确认添加契约、集成与验收测试及小型固定输入。检查行为与需求，避免复刻实现。
修改失败用例的期望值需有需求或决策依据。

## 4. 禁止修改范围

不得通过删测试、放宽阈值或重写产物掩盖失败；不得覆盖研究数据或checkpoint。
测试默认不启动长训练、不依赖研究模型或GPU完成占位接口验证。

## 5. 与其他模块接口关系

从公开入口测试生产者与消费者；实验记录由experiments维护，验收关联到
DEVELOPMENT_PLAN中的需求和阶段门槛。

## 6. 测试要求

至少规划时间、坐标、未知区域、占位/真实模式、重复帧、断流/超时、地图老化、回放
一致性和资源边界检查。性能阈值先确认，不能以一次成功或平均耗时代替完整验收。
训练数据生成还须覆盖Radar/IR/LiDAR监督的时间与外参、observed mask、输入标签隔离，
以及inference启动图无LiDAR生产者/订阅者；Odometry镜像不得绕过SpatialContext门控。

## 7. 文档要求

每项检查记录目的、前置条件、输入、预期、执行方式、实际结果和限制。
报告区分语法检查、功能测试、模型质量和场景验收；结果索引进入EXPERIMENT_LOG。
